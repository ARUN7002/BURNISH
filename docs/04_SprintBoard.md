# Purpose

The Sprint Board defines the engineering roadmap for the Burnish MVP.

Instead of developing features randomly, the project is divided into focused development sprints. Each sprint delivers a working part of the product that contributes directly to the final hackathon demonstration.

Every sprint ends with a testable outcome.

# Development Principles

During implementation, Burnish follows these principles.

- Build one working feature at a time.
- Test every sprint before moving forward.
- Keep the architecture modular.
- Maintain clear documentation.
- Commit changes frequently.
- Never sacrifice stability for unnecessary features.

---

# Definition of Done

A sprint is considered complete only if:

- All planned tasks are implemented.
- Code runs without critical errors.
- Feature has been tested.
- Documentation is updated.
- Changes are committed to GitHub.

---

# Overall MVP Goal

At the completion of all sprints, Burnish will allow users to:

- Connect to DataHub
- Scan metadata
- Detect governance issues
- Generate AI recommendations
- Explain reasoning
- Approve recommendations
- Update metadata
- Review audit history

The MVP will provide a complete governance workflow suitable for demonstration during the DataHub Agent Hackathon.

---

# Key Takeaways

- Development is divided into manageable sprints.
- Every sprint delivers a working feature.
- Each sprint contributes directly to the final demo.
- Stability and completeness take priority over feature quantity.
